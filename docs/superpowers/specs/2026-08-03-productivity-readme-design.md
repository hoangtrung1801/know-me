# Productivity README Design

## Goal

Reposition Know-Me as a local-first productivity workspace for organizing projects and tasks, saving useful links, and capturing quick memos.

## Scope

- Rewrite the root English `README.md` and Vietnamese `README.vi.md`.
- Remove coding-project and AI-agent-first positioning from their product copy.
- Keep installation, command reference, documentation, development, and project links relevant to the product.
- Do not change application behavior, CLI commands, documentation pages, or assets.

## Content Structure

Each README will use the same structure in its respective language:

1. A concise productivity-focused hero and value proposition.
2. A problem statement about scattered work, bookmarks, and notes.
3. A short before-and-after comparison.
4. An explanation of the local-first workspace model.
5. Core capabilities: projects, tasks, saved links, and memos.
6. A quick start using existing CLI commands for those capabilities.
7. Existing installation, documentation, development, and repository links, revised only where their copy conflicts with the new positioning.

## Product Claims

- Projects organize related work.
- Tasks track work and progress.
- Saved links provide a global library available across projects.
- Memos capture short global notes.
- The tool remains local-first and self-hostable.

## Consistency Rules

- English and Vietnamese README sections communicate the same product value.
- Do not claim features that do not exist.
- Keep technical contributor information, but make it secondary to the product message.
- Preserve existing language, documentation, installation, and community links where valid.

## Validation

- Confirm both files have matching high-level sections and working internal anchors.
- Search both READMEs for obsolete coding-first hero copy and remove it.
- Verify the markdown diff only changes the two README files and this design document.
